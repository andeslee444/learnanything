### Task 1: Block sanitizer + share service

**Files:** llmObject purpose `'sanitize-block'` + fixture, `src/server/lessons/sanitize.ts`, tests

- New purpose `'sanitize-block'` (generator tier): input = one block's JSON + the lesson's dossier extracts (spotlighted, data-never-instructions); output schema `{action: 'keep'|'rewrite'|'drop', block?: <same block shape>, reason: string ≤200}`. System prompt (spec §7 core): scan for learner-derived content — mission framing ("your goal", "since you want to…"), prior-knowledge bridges ("as you saw when…", "like in your last lesson"), personalized examples, learner identity (names, ages), learning-record references; `keep` only when fully generic; `rewrite` = regenerate the block's prose from the dossier extracts with NO personalization (same block type/shape, citations preserved from the original block's citation ids); `drop` for opener-retrieval blocks and anything unrewritable. Fixture: deterministic per block type (article → rewrite with fixed generic text incl. original citations; quiz/glossary/worked example/diagram/flashcards → keep; win-check → keep; opener items → drop) so fake-mode produces a stable sanitized lesson.
- `sanitize.ts`: `sanitizeLessonContent(db, lesson)` → `{content, dropped: string[], rewritten: string[]}` — iterate blocks; opener-retrieval items always dropped deterministically BEFORE the LLM (cheap, spec-mandated — they are learner-history by construction); per-block llmObject sanitize-block; then run the EXISTING validate pipeline pieces that apply to a sanitized whole (validateLessonContent with the source lesson's spec objective — relax the opener requirement: pass a flag or strip opener expectations; check validate.ts for what's parameterizable; do NOT fork the validator — extend with an options param `{requireOpeners: boolean}` defaulting true) + a moderation pass (`assembled_lesson` context, most-conservative band '13_15' — public pages are read by anyone; comment this). Deterministic guard AFTER the LLM: reject (fail share) if any sanitized text still contains the learner's displayName (case-insensitive) — cheap last line.
- Tests: fixture path produces stable content; openers always dropped pre-LLM; displayName leak guard (seed a block whose fixture-rewritten text is forced to contain the name via a crafted block — simplest: unit-test the guard function directly with synthetic content); validator options param backward-compatible (existing callers unchanged — run full suite).
